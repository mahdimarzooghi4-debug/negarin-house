# Customer web native Figma preview

Source: [Customer / Web, canvas 1174:14](https://www.figma.com/design/Uo0ifnpFmJFhWqaEVmVOZ1/Negarin-House?node-id=1174-14).

All 19 source frames are enabled at `/preview/customer-web`: home, products, product detail, cart, login, OTP verification, address book, checkout review, orders, order detail, artist store, artist stories, story viewer, payment redirect/success/failure, favorites, favorites empty, and account overview. The catalog and inventory account for every top-level source screen. No tablet layout is introduced.

The reference canvases retain native 1440px desktop geometry and source height, Persian text, scoped CSS, locally packaged Vazirmatn and Material Icons Round, and 94 complete original exports (71 PNG/23 SVG) in 146 image callsites. All original logos and footer fills are preserved, including the light footer on which the Negarin logo remains visible. No screenshots are used as page backgrounds and no replacement imagery or hand-drawn icon paths are introduced. SVG exports disable stroke simplification. Export bytes are complete and verified before writing public files; two PNG exports changed between native renders and their latest complete export hashes were recorded against the same native node IDs. Final native layout dimensions were retrieved after source fonts resolved. The selected gallery thumbnail retains its original border over the photo without shrinking the exported photo twice.

All 1,040 retrieved container/instance boxes and 665 scoped utility groups are saved in native React/CSS. Shared semantic controls make navigation and native buttons keyboard accessible, preserve local editable form fields, and avoid nested actions. The native FRAME/INSTANCE/COMPONENT/TEXT reaction audit found zero reactions: preview navigation is explicitly inferred, not claimed as a source prototype. Source headers, artwork actions, artist/story links, cart/login/address/review flow, account and footer destinations remain within the customer web preview. The catalog also exposes all payment and empty-state reference screens directly.

Login validates a Persian or Latin 11-digit Iranian mobile number beginning 09. OTP accepts only sample 123456 and then opens address book. Six address fields are editable local drafts. The save-address action opens the sample review screen; it does not save a real address. Review opens the source payment-redirect reference; it does not open an external gateway or start a charge. Static payment outcomes do not establish payment verification. Cart prices, quantities, total, order identities, addresses, favorites and account summary counts retain source sample content. Quantity, filtering, share, follow, save/delete and account controls acknowledge preview scope where no real operation is implemented. No OTP SMS, authentication, address persistence, order, payment or backend integration is implemented in this change.

Use `pnpm --filter @negarin/web dev` and open `/preview/customer-web`. Production previews are disabled unless `NEGARIN_UI_PREVIEW=1`. The existing role portals and backend remain unchanged.

Validation: web build, ESLint and all 7 web unit tests passed. All 4 customer web Playwright tests passed: every route/original asset and visible native image bounds, catalog/navigation/product-to-cart flow, phone/OTP validation and address-to-review-to-payment flow, and payment/favorites/account/order references. All 19 screens rendered with zero page/hydration errors, zero broken assets, zero asset-path mismatches and zero visible original-image bound outliers beyond 2px across 146 slots. Geometry checks account for ancestor clipping and exported native stroke/render bounds. Selected visual comparisons included home, login and checkout review; this does not claim full pixel equivalence or adaptive production readiness.

Coverage and evidence: `customer-web-screen-inventory.json`, `customer-web-asset-slots.json`, `customer-web-controls.json`, `customer-web-source-reactions.json`, and `customer-web-ui-verification.json`.
